# 별 키우기 사용자 준비 사항

작성일: 2026-10-12. 구현은 에이전트에 맡길 수 있지만 개발자 계정의 소유자 확인, 서명 키 보관, 실제 기기와 테스트 참여자 확보, 법적 신고 내용의 확인은 사용자의 준비가 필요하다. 이 문서는 [게임 명세](superpowers/specs/2026-10-12-star-game-design.md)와 [구현 계획](superpowers/plans/2026-10-12-star-game.md)을 전제로 한다.

## 1. 구현 시작 전에 정할 것

무료·인앱결제 없음·광고 포함, 초기 기기 내 저장과 후속 DB 서버 로그인·복구, Git 보관은 사용자 확정 사항이다. 나머지는 아래 기본안을 따른다. 계정 정보가 늦어도 게임 구현과 테스트 광고 검증은 먼저 진행할 수 있다.

| 항목 | 확정 사항 또는 권장 기본안 | 언제까지 |
| --- | --- | --- |
| 게임 범위 | 1개 별 육성, 6단계 성장, 6종 도감, 재화·강화 각 1종 | 구현 시작 |
| 수익화 | 확정: 무료·인앱결제 없음·광고 포함. 권장: AdMob 홈 배너 1개 | 확정 완료; 광고 계정은 출시 전 |
| 이름 | 작업명 ‘별 키우기 · ZeroStar’; 스토어 검색·권리 확인 후 최종 이름 결정 | 스토어 자료 제작 전 |
| 출시 시장·언어 | 대한민국 Google Play, 한국어 | 스토어 설정 전 |
| 대상 이용자 | 휴식형 캐주얼 이용자. 실제 연령 대상과 스토어 등급 설문 확인 | 콘텐츠·스토어 확정 전 |
| 저장 정책 | 확정: 초기에는 이 기기에만 저장. 후속 DB 서버 로그인·복구 구현. 초기 삭제·기기 변경 시 복구 보장 없음 | 초기 정책 확정 완료; 서버는 후속 단계 |
| applicationId | 소유자 기준으로 유일하고 장기 사용할 값 | 첫 Play 업로드 전 |
| 디자인 자산 | ZeroVerse 스타일 참조와 필요한 자산의 사용 권리 확인 | 최종 자산 반영 전 |
| 소스 보관 | 확정: Git 관리. 원격 서비스·주소·공개 범위는 사용자 지정, 비공개 권장 | 로컬 Git은 구현 시작; 원격 정보는 준비 시 |

광고는 초기 구현에 포함한다. 보상형·전면 광고와 인앱결제는 기본안에 넣지 않는다. 후속 로그인·복구를 초기 출시의 선행 조건으로 만들지 않으며 서버 호스팅·DB·인증 제공자도 지금 준비할 필요는 없다.

## 2. 가장 먼저 준비할 계정과 테스트 참여자

- [ ] Google Play Console 소유 계정을 준비하고 개인/조직 유형을 실제 주체에 맞게 선택한다. 등록 비용은 가입 화면에서 확인하고 사용자가 결제한다. [계정 시작 안내](https://support.google.com/googleplay/android-developer/answer/6112435)
- [ ] 신원·연락처·기기 확인 등 계정에 표시되는 필수 인증을 완료한다. 조직 계정이라면 조직 증빙 등 해당 요구를 확인한다.
- [ ] 계정 생성일과 프로덕션 액세스 상태를 확인한다. 2023-11-13 이후 생성된 개인 계정에 안내된 조건은 최소 12명이 연속 14일 참여하는 비공개 테스트 후 액세스 신청이다. 실제 테스트와 피드백이 필요하며 승인까지 추가 시간이 걸릴 수 있다. [테스트 요구](https://support.google.com/googleplay/android-developer/answer/14151465)
- [ ] 대상 계정이면 이탈을 감안해 15~20명 모집을 권장한다. 15~20명은 이 계획의 여유 인원이며 Google의 최소 조건은 아니다. 테스터에게 Google 계정·Android 기기·참여 유지·실제 플레이와 피드백을 요청한다.
- [ ] 첫 사용성 점검용 최소 3명을 먼저 확보한다. 이 사람들은 비공개 테스터와 겹쳐도 된다.
- [ ] 사용자 소유의 지원 이메일을 준비한다. 문의를 받을 수 있는 주소여야 한다.
- [ ] 광고 기본안에 따라 AdMob 소유 계정을 준비하고 광고 앱 ID·배너 광고 단위 ID를 제공한다. 앱 등록·정책·결제 프로필·본인 확인 등 계정에 표시되는 필수 항목을 처리한다. 테스트 광고로 개발을 먼저 진행할 수 있다. [AdMob 안내](https://developers.google.com/admob/android/quick-start)
- [ ] 광고 개인정보 메시지와 실제 대상 연령·출시 국가에 맞는 설정을 확인한다. 광고 계정/앱 검토와 요구되는 app-ads.txt·소유 확인을 처리할 공개 개발자 웹 주소 및 게시 권한을 준비한다. 실제 요구 사항은 사용 계정과 최신 사업자 안내로 확인한다.
- [ ] Git 커밋 작성자 이름·이메일을 정한다. 원격 백업을 원하면 사용자 소유 저장소 URL·공개 범위·접근 권한을 준비한다. 비공개 저장소를 권장하며 토큰은 채팅이나 문서에 적지 않는다.

계정 비밀번호·OTP·신분증을 채팅에 붙여넣지 않는다. 소유자가 직접 로그인·인증하고 필요한 경우 최소 권한으로 작업을 연결한다. 에이전트가 실제 테스터나 신원 인증을 대신 만들어낼 수는 없다.

## 3. 개발 PC와 Android 기기

최초 조사 당시 Windows 작업 폴더는 비어 있었고 JDK 21, Git, Node는 PATH에서 확인되었다. 현재는 계획 문서가 있으며 Git 저장소 초기화는 구현 시작 작업으로 계획했다. Android Studio와 Android SDK는 기본 경로에 없고 adb는 PATH에서 확인되지 않았다. 다른 경로 설치 여부는 추가 확인 대상이다.

| 준비물 | 사용자 할 일 | 에이전트 할 일 |
| --- | --- | --- |
| Android 개발 도구 | 설치 권한·디스크·네트워크 제공, 필요한 약관 처리 | 기존 설치 검색, 호환 JDK/SDK/Gradle 선정·설정 |
| 에뮬레이터 | 필요한 가상화 설정·설치 허용 | API 26/API 36, 16KB 이미지 구성·검증 |
| 보급형 실기기 | Android 기기 1대, 가능하면 4GB급과 낮은 성능 구간 | 설치·종료·저장·성능 측정 |
| 최신 실기기 | 최신 Android가 동작하는 별도 기기 1대 또는 장치 테스트 접근 | 최신 OS·인셋·수명주기 검증 |
| USB 연결 | 데이터 케이블, 개발자 옵션·USB 디버깅 승인, 드라이버 필요 시 설치 | adb 연결 확인과 재현 가능한 테스트 |
| 물리 접근이 어려운 경우 | 실제 기기 실행과 캡처를 할 담당자·시간 제공 | 정확한 실행 절차·체크리스트·로그 수집법 제공 |

기기가 한 대뿐이면 다른 한 대를 빌리거나 원격 실기기 테스트 수단을 확보한다. 유료 장치 서비스는 별도 비용 승인을 받은 경우에 사용한다. 에뮬레이터만으로 ‘실기기에서 원활함’을 확정하지 않는다.

## 4. 서명과 배포 정보

- [ ] 최종 applicationId와 개발자 표시명을 확정한다. applicationId는 첫 업로드 뒤 다른 앱으로 쉽게 바꿔 쓰는 값이 아니다.
- [ ] Play App Signing 사용과 업로드 키 관리 방식을 정한다. 사용자 소유 키를 생성하거나 제공하고, 키스토어·별칭·암호를 안전한 로컬/비밀 저장소에 보관한다.
- [ ] 키와 복구에 필요한 정보를 별도 안전한 위치에 백업한다. 키 파일과 암호를 소스 저장소나 공유 문서에 넣지 않는다.
- [ ] 서명된 빌드를 테스트하고 같은 키로 업데이트 설치되는지 확인할 시간을 확보한다.
- [ ] 에이전트에게 허용할 범위를 정한다: 로컬 빌드 / Play 내부·비공개 테스트 업로드 / 최종 공개 배포. 구현 위임은 공개 배포 지시와 구분한다.

업로드 키와 Google이 관리하는 앱 서명 키를 구분해서 기록한다. 앱 소유권과 계정 복구 수단은 사용자에게 남아야 한다.

## 5. 스토어 제출에 필요한 자료

| 자료 | 에이전트가 준비할 것 | 사용자가 제공·확인할 것 |
| --- | --- | --- |
| 스토어 문구 | 앱명 후보, 짧은 소개, 상세 설명, 릴리스 노트 | 최종 이름, 권리 문제, 공개 내용 |
| 시각 자료 | 아이콘, 대표 이미지, 실제 앱 스크린샷 4장 | 이름·브랜드·사용 권리 |
| 개인정보처리방침 | 실제 저장·전송 동작에 맞는 본문, 앱 내 링크 | 운영 주체, 연락처, 공개 호스팅 위치/권한 |
| 데이터 보안 | 광고 SDK를 포함한 라이브러리·권한·수집/공유 동작을 근거로 답변 초안 | 최종 신고 확인 |
| 앱 콘텐츠 | 광고 포함, 인앱결제 없음, 초기 로그인 불필요, 게임 내용·대상 설명 | 대상 연령·출시 국가·콘텐츠 등급 설문과 법적 확인 |
| 광고 설정 | 배너·동의 흐름·개인정보 선택·테스트 광고 검증 | 광고 계정, 실제 앱/단위 ID, 필요한 앱 검토·소유 확인 |
| 지원 | 문의 링크·오류 재현 안내 | 지속 사용 가능한 이메일 |
| 테스트 | 설치 절차·피드백 양식·수정 기록 | 참여자와 실제 피드백 |

로컬 게임 저장과 광고 SDK의 정보 처리를 구분해 공개 개인정보처리방침과 데이터 보안 양식을 작성한다. 자체 게임 서버가 없다는 이유로 ‘수집 없음’을 신고하지 않는다. 웹 정책 페이지는 로그인 없이 열려야 하고 실제 앱의 데이터 처리와 일치해야 한다. [데이터 보안 안내](https://support.google.com/googleplay/android-developer/answer/10787469)

앱 내 정책에는 로컬 진행 저장, 광고 SDK의 외부 수집·공유, 필요한 개인정보 선택 방법, 삭제 방법, 초기 기기 변경 한계, 문의 수단을 설명한다. 동의·개인정보 선택은 해당 지역과 SDK 요구에 맞춰 구현한다. [UMP 안내](https://developers.google.com/admob/android/privacy) 개인정보처리방침을 여는 외부 브라우저와 사용자가 보내는 문의 이메일의 처리도 구분해 설명한다.

출시 국가의 게임 등급과 계정별 요구는 실제 콘솔과 해당 공식 안내를 확인한다. 한국 출시라는 이유로 별도 등급 절차가 언제나 필요하다거나 언제나 면제된다고 가정하지 않는다. 앱 내 구매가 없는 현재 범위를 기준으로 확인한다.

## 6. 비용과 시간

| 항목 | 기본안 |
| --- | --- |
| Play 개발자 등록 | 소유자가 등록 화면의 현재 금액 확인·결제 |
| 자체 게임 서버 | 초기에는 사용하지 않음. 후속 DB 서버·인증·백업·운영 비용은 별도 산정 |
| 광고 | SDK 연동·개인정보 처리·검토 시간 필요. 수익과 광고 채움률은 보장하지 않음 |
| 정책 페이지 | 기존 공개 웹 공간 또는 무료 정적 호스팅 사용 가능; 커스텀 도메인은 필수 아님 |
| 그래픽·글꼴·효과음 | 직접 제작 또는 재배포 가능한 자산 우선. 유료 구매는 사전 승인 |
| 테스트 기기 | 보유·대여 우선. 클라우드 실기기나 새 기기 비용은 선택 별도 |
| 에이전트 사용 | 계정·모델·검증 반복에 따라 비용 발생. 고정 금액 보장 없음 |
| 일정 | 광고 연동 포함 개발·검증 9~18개 작업일을 초기 가정으로 예약. Play/광고 계정 검토·테스트 기간은 별도 |

가장 먼저 Play·광고 계정 상태와 테스터를 준비한다. 안정된 테스트 빌드를 만든 뒤 필요한 연속 테스트 기간을 채워야 하므로, 계정 준비를 마지막에 미루면 출시가 지연된다. 에이전트 작업 완료와 Google 승인 날짜를 동일하게 약속하지 않는다.

## 7. 사용자 확인 순서

1. **시작:** 확정된 무료/광고 포함/무결제·초기 로컬 저장·Git 관리 정책에 따라 구현을 지시한다.
2. **병행 준비:** Play·광고 계정, Git 작성자/원격 정보, 연락처·테스터·실기기를 확보한다.
3. **플레이 가능한 빌드:** 사용자와 3명이 첫 성장·복귀·등록 흐름을 점검한다. 큰 기능 추가보다 이해하기 어려운 부분을 알려준다.
4. **배포 후보:** 최종 이름·applicationId·광고 ID와 설정·키·정책 URL·스토어 문구를 확정한다.
5. **테스트 배포:** 필요한 내부/비공개 테스트와 계정별 신청을 진행한다.
6. **최종 검토:** 에이전트가 제시한 RELEASE-READINESS의 증거와 산출물을 확인하고 실제 제출·공개 시점을 지시한다.

## 8. 최종적으로 받을 산출물

- Git에 보관된 전체 소스·문서·테스트, 릴리스 커밋/태그, 고정된 빌드 환경 정보, 재빌드·기기 설치 방법. 연결한 원격이 있으면 push/백업 상태도 전달.
- 서명 AAB와 테스트용 APK, 해시·버전·인증서 지문.
- 실기기별 기능·성능·저장 테스트 결과와 제한 사항.
- 실제 앱 스크린샷·아이콘·대표 이미지·스토어 설명.
- 개인정보처리방침 본문/공개 링크, 데이터 보안 답변 근거, 자산 라이선스 목록.
- 광고 테스트 결과, 실제 광고 ID·설정 점검표, 계정/앱 검토 상태. 비밀 자격증명은 별도 보관.
- 계정별 배포 조건 확인과 `RELEASE_READY` 체크리스트.
- 업데이트 절차와 사용자만 보관하는 서명·복구 수단.

사용자 준비가 끝나지 않으면 에이전트는 준비 가능한 산출물을 먼저 완성하고 남은 입력을 명시해야 한다. `TECHNICALLY_READY`나 대기 상태를 최종 성공으로 바꾸지 않는다. 실제 공개 여부와 심사 결과는 별도로 확인한다.

## 9. 후속 서버 단계에서 준비할 것

초기 출시 후 DB 서버 로그인·진행 복구를 구현할 때 서버 호스팅 예산·운영 주체, 인증 방식, DB와 백업 정책, 계정 삭제·데이터 보관 정책을 정한다. 처음 로그인할 때 기존 기기 진행을 계정에 옮기는 방식, 로컬/서버 진행 충돌 처리, 재설치·기기 변경 복구를 명세하고 검증한다. 초기에는 이 서비스들이 없는 상태로 출시하며 아직 제공되지 않는 복구 기능을 스토어에서 약속하지 않는다.

## 구현 작업 이후 재개에 필요한 항목 (2026-10-12 UTC)

- SDK 설치와 사용자 직접 약관 동의는 진행했다. CLI의 `--licenses option is no longer needed` 출력 자체는 동의나 설치 증거가 아니다. 실제 설치 목록은 artifacts/logs/sdk-installed.txt에 기록했다.
- 초기 에뮬레이터 부팅은 C: 용량(당시 약5GB)으로 차단됐지만 사용자 공간 확보 후 해결했다. API26 32개·API36 일반31개·실제16KB33개 장치 검사를 통과했다. 이후 작업용 API26 이미지/AVD 정리로 약11.44GiB를 확보했다. 사용자 파일은 삭제하지 않았다. 실기기2대 요건은 별도로 남아 있다.
- 클라우드 개발 가능 여부 질문은 이전/업로드 승인과 다르다. 연결된 클라우드 실행 환경과 가상화 지원은 미확인이다. 전환은 미실행.
- 실기기 2대, 3명 플레이 피드백, 최종 패키지/버전/출시 국가/연령/문의 이메일, 실제 광고 ID와 계정·동의 메시지, 공개 정책 URL, 사용자 보관 업로드 키가 필요하다. 키·암호는 채팅에 보내지 않는다.
- 권한·계정 준비 후 내부/비공개 테스트, 실제 프로덕션 액세스 승인과 국가별 요구를 확인한다. 실제 스토어 공개·유료 지출·원격 push는 별도 지시 전 하지 않는다.
- 상세 재개 명령과 증거: docs/release/RELEASE-RUNBOOK.md, docs/release/RELEASE-READINESS.md, docs/qa/DEVICE-MATRIX.md.


### 최신 환경 / 추가 입력 (2026-10-12)

API26 이미지를 독립 테스트를 위해 다시 설치했다. C: 여유5.63GiB에서 이미 설치된16KB AVD가 정상 실행됨을 재확인했다. 지금 추가 공간 확보가 기존 AVD 부팅의 선행 조건은 아니다. 호스트 GPU/메모리의 검증 제한은 OS-EDGE-RESULTS에 기록했다.

Google Publisher Test Ads의 거부 선택과 이어지는 개인정보 선택 검사는 자동 승인 검토가 법적 입력 경계를 이유로 차단했다. 테스트 화면의 거부 선택만 명시적으로 허용하거나 직접 조작해야 해당 검사 재개가 가능하다. 실제 법적 동의 수락·계정 약관·인증은 계속 사용자가 직접 처리한다.

최신 동의 검사 상태(2026-10-13 UTC): 두 번째 거부 선택의 별도 허용 후 기존 거부 상태를 보존한 재개 프로브에서 개인정보 양식 거부·정상 닫기까지 통과했다. 이 선택에 대한 추가 승인은 필요하지 않다. 과거 차단/실패와 후속 결과는 CONSENT-APPROVAL-BLOCK.md에 구분해 보존한다. 실제 광고 계정·정책·실기기 등 출시 입력은 계속 필요하다.
